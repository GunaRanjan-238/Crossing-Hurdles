The kvdex library (`@olli/kvdex`) exposes a rich set of "by secondary index" query helpers on its indexable collections. The analogous "by secondary order" bulk operations, however, are absent from the collection type in `src/collection.ts`, so the secondary-order API there remains incomplete. Separately, the map-backed KV extension currently resides under `src/ext/map_kv/`; a cleaner `src/ext/kv/` module layout houses this extension instead, with imports and the public documentation reflecting the new location.

Concretely, add the many/one secondary-order methods to the collection so that a caller can operate over documents sorted by a secondary index rather than by id: implement `getManyBySecondaryOrder(order, options?)` to retrieve multiple documents in the specified secondary order (with no options meaning "all documents", and support for a `filter` predicate over each `doc`), `getOneBySecondaryOrder(order, options?)` for the first matching document, `updateManyBySecondaryOrder(order, data, options?)` and `updateOneBySecondaryOrder(order, data, options?)` to update documents in that order (e.g. update the first 10 users ordered by `age`, setting `username = "anon"`), `deleteManyBySecondaryOrder(order, options?)` to delete documents in that order (honoring optional filtering and pagination via `limit`, deleting all when no options are given), and the iteration helpers `forEachBySecondaryOrder`, `mapBySecondaryOrder`, and `countBySecondaryOrder` following the same ordering semantics as their existing `BySecondaryIndex` counterparts. These must interoperate with both the plain indexable collection and the serialized indexable collection.

The map-backed KV extension lives under `src/ext/kv/` rather than `src/ext/map_kv/`. In the new layout, the module previously at `src/ext/map_kv/kv.ts` corresponds to `src/ext/kv/map_kv.ts`, and `atomic.ts`, `utils.ts`, and `watcher.ts` reside under `src/ext/kv/`. The module additionally includes `src/ext/kv/mod.ts`, `src/ext/kv/storage_adapter.ts`, and `src/ext/kv/types.ts`, while `src/ext/map_kv/storage_adapter.ts` no longer exists. `MapKv` is exported from `src/ext/kv/map_kv.ts`, and `StorageAdapter` is exported from `src/ext/kv/mod.ts`. Everything continues to work offline under Deno with the existing test task (`deno test --allow-write --allow-read --allow-ffi --allow-sys --unstable-kv --trace-leaks`). `README.md` documents the new secondary-order methods and includes a `KV` section, and `deno.json` reflects any necessary changes. The relocated tests under `tests/ext/kv.test.ts` import `MapKv` from `../../src/ext/kv/map_kv.ts` and `StorageAdapter` from `../../src/ext/kv/mod.ts`, so those paths must resolve.
